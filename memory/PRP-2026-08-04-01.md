## 一、项目背景情况

### 1. 项目目标

项目研究可变固体/流道配置下的水冷散热问题。传统数值模拟器负责生成可信数据，后续使用神经网络近似映射，并利用神经网络的可微性优化物体配置。

项目不只关注温度场预测，还关心水力代价。当前最简性能输出为：

- 热源区域最高稳态温度；
- 入口相对出口的压力差；
- 入口体积流量。

后续配置优化应至少同时考虑最高温度和水力代价，避免只降低温度而忽略压降、流量或泵功。

### 2. 当前数值模型

- Python + NumPy + Numba；
- 二维 D2Q9 LBM；
- `f` 表示流体密度/动量分布；
- `g` 表示温度分布；
- 固体和流体使用不同热扩散率；
- 左侧为给定速度与温度入口；
- 右侧为给定参考密度的压力出口；
- 上下边界采用反弹/绝热处理；
- 障碍物由 `py/graph.py` 生成或读取；
- 温度格子量采用 `Tc -> 0`、`Th -> 1` 的归一化。

### 3. 当前配置

`config.toml` 主要参数：

```toml
Nx = 200
Ny = 200
U0x = 0.05
U0y = 0.00

X = 0.01
Tc = 273.15
Th = 333.15

C_l = 4182

```

`U0x` 是格子入口速度，`Ux` 是对应的真实速度尺度。两者共同决定 `deltat` 与速度转换系数。

## 二、项目现状

### 1. 开放边界与 NaN 问题

此前 NaN 主要表现为异常从出口附近开始并向域内传播。经过检查后，入口/出口改为按格点情况组织的全方向非平衡外推：

- 入口：规定 `U0` 和入口温度，密度沿用内部参考节点；
- 出口：规定 `Rho0 = 1`，速度和温度沿用内部参考节点；
- 同一边界格点的全部方向使用同一个法向内部参考节点；
- 上下角点采用反弹处理；
- 固体边界与流体边界分别处理。

修复后观察到：

- 原有出口 NaN 问题消失；
- 出口密度基本稳定为 1；
- 当前复杂配置能够稳定收敛；
- 格子速度过高仍会提高弱可压缩误差和失稳风险，不能把边界修复理解为无限扩大适用范围。

### 2. 压力解释与单位转换

标准 D2Q9 中：

```text
p_lu = cs_lu^2 * rho_lu
cs_lu^2 = 1/3
```

以出口 `rho0_lu = 1` 为参考，格子表压为：

```text
delta_p_lu = (rho_lu - 1) / 3
```

物理压力差转换为：

```text
delta_p_phys
= delta_p_lu * rho_ref * deltax^2 / deltat^2
```

注意：格子密度扰动主要承担压力变量作用，不应直接解释为水的真实热力学密度变化。

一次已完成的 `config` 收敛运行得到：

```text
最高热源温度                 278.6603966 K
入口平均格子密度             1.0164599786
入口相对出口格子压差         0.00548665953
入口相对出口物理压差         21.9027449 Pa
收敛步数                     约 13409
```

物理压力转换系数为 `3992 Pa / lattice-pressure-unit`，与 `Rho_l = 998 kg/m^3` 及当前速度转换相符。

### 3. 性能报告

`controller.report_performance()` 当前返回字典：

```python
{
    "max_source_temperature_k": ...,
    "pressure_drop_pa": ...,
    "volume_flow_rate_m3_s": ...,
}
```

定义：

- 最高温度统计 `source_delta_T > 0` 的发热区域；
- 压力使用入口截面去除上下角点后的平均密度；
- 体积流量使用入口截面水平方向宏观速度之和；
- 当前 `V_l * deltax**3 / deltat` 隐含二维模型的第三维厚度等于 `deltax`，报告中必须声明该准三维假设。

固定入口速度时，体积流量主要描述工况；结构差异主要反映在最高温度和压差/泵功中。

### 4. 可靠性报告与收敛判断

快照已托管给 `run_one_step()`：推进前使用 `.copy()` 保存 `U_pre` 和 `T_pre`。主循环顺序已经调整为：

```text
周期性保存当前场
-> run_one_step()
-> report_reliability()
-> 判断是否收敛
```

`report_reliability()` 当前使用三个相对变化量：

```python
{
    "velocity_field_relative_change": ...,
    "temperature_field_relative_change": ...,
    "source_peak_temperature_relative_change": ...,
    "stable_checks": ...,
    "converged": ...,
}
```

速度场和温度场使用相邻时间步 RMS 变化，并以当前/上一时刻 RMS 的较大值归一化；热点变化以当前/上一时刻热点的较大值归一化。当前主循环阈值均为 `1e-4`，要求连续 3 次通过。

已决定从可靠性停止条件中移除出口带热代理量。该代理量 `sum(max(ux, 0) * T)` 是速度场和温度场的派生量，与现有检查重叠，而且不是完整物理热功率。真实能量平衡留到有效性检验阶段单独完成。

### 5. 当前可靠性代码的已知清理项

以下问题在开始正式有效性检验前应修正：

1. `final_report(self, reliability)` 当前忽略传入的 `reliability`，内部再次调用 `self.report_reliability()`；这会在同一时间步重复推进 `stable_checks`。应直接使用传入字典，或者实现按时间步缓存后改成无参数 `final_report()`。
2. `report_reliability()` 的注释仍提到出口带热量，应更新。
3. 旧的 `error()` 辅助函数已无调用方，可删除。
4. 首次检查分支在当前“先运行、后报告”的主循环下通常不会进入，但可作为防御性逻辑保留或进一步简化。
5. 收敛发生在 `run_one_step()` 之后，日志中的 `n` 实际对应完成 `n+1` 步；周期性文件保存放在推进前，因此 `write(0)` 表示初始场、`write(200)` 表示已完成 200 步的场。
6. 同一步重复调用 `report_reliability()` 仍会重复增加 `stable_checks`；若未来有多个调用方，应增加本步结果缓存或 step-id 防重复机制。

### 6. 体积流量与质量守恒

二维格子单位下，单位厚度体积流量为：

```text
q_lu' = sum_j ux(i, j)
```

质量流量代理为：

```text
m_lu' = sum_j rho(i, j) * ux(i, j)
```

弱可压缩 LBM 中入口和出口体积流量可以因密度不同而略有差异，但稳态质量流量应一致。密度同时承载压力信息不能解释稳态质量不守恒。

物理三维体积流量的一般转换为：

```text
Q_phys = q_lu' * deltax^2 / deltat * depth
```

### 7. 几何生成与 padding

`py/graph.py::cell_noise()` 已增加 `padding` 参数。围绕 padding 的需求已经重新澄清：

- 最初实现限制相邻 cell 中随机中心点的最小间距；
- 当前真正希望实现的是障碍物边缘必然留出流体空隙，从而避免极端狭窄或完全堵塞结构；
- 仅规定中心位置不能在任意尺寸下保证边缘间距；
- 正确方案是先生成实际 `szx/szy`，再用 `实际半尺寸 + edge_padding` 限制中心可选范围；
- 相邻 cell 的障碍物由此至少留下约 `2 * edge_padding` 的通道。

当前代码尚未完成上述“边缘间距保证”：

- 仍采用单侧中心 padding；
- `padding` 当前默认值为 `0.4`；
- `seed` 初始化仍被注释，生成不可复现；
- 文件顶层仍直接调用 `cell_noise((400,400))`，导入 `graph` 时会覆盖输出图片；
- 生成图可能从 400x400 缩放到 200x200，最终通道宽度会缩小并受到插值/二值化影响。

后续应在最终模拟分辨率上检查：

- 入口到出口连通性；
- 最小通道宽度；
- padding 经缩放后的实际格点数；
- 随机种子复现性。

### 8. 工况、性能与可靠性的分类

已经确定：

- `performance`：最高温度、压力差、体积流量；
- `reliability`：收敛、守恒、LBM 数值适用性；
- `regime`：全局 `Re/Ra/Pr` 等工况描述。

全局 `Re/Ra` 不直接证明结果可靠，应作为独立工况元数据。局部最大 Re 很高也不必然表示全场失效；局部诊断应优先使用：

- 最大与 P99 网格雷诺数；
- 最大 Mach 数；
- 最大密度相对扰动；
- 超过警戒值的流体格点比例；
- 异常区域是否位于热点或关键流道附近。

局部 Rayleigh 数依赖局部特征长度的三次方，定义不稳定，暂不建议作为局部最大可靠性指标。

## 三、项目计划情况

### 1. 模拟器阶段判断

模拟器的主要功能开发基本完成。下一阶段不是继续堆叠功能，而是进行数值验证、物理有效性检验和求解器冻结。验证未完成前，不应大规模生成神经网络训练数据。

### 2. 验证前代码清理

优先处理：

1. 修正 `final_report()` 对可靠性结果的重复计算；
2. 完成或明确取消同一步可靠性缓存；
3. 清理可靠性旧注释与无调用辅助函数；
4. 完成 edge-padding 几何约束；
5. 恢复随机种子复现；
6. 将 `cell_noise((400,400))` 移入 `if __name__ == "__main__":`；
7. 固定最终报告字段与单位。

### 3. 数值验证 Verification

必须完成的基础测试：

1. 无障碍通道：速度剖面、压降与 Poiseuille 理论/高可信参考比较；
2. 纯导热问题：稳态线性温度分布或有解析解的简单热源问题；
3. 质量守恒：入口与出口 `sum(rho * ux)` 的相对残差；
4. 能量守恒：热源输入、域内储能变化、出入口对流热流及必要导热项之间的平衡；
5. 网格无关性：保持真实几何与物理尺度一致，对不同分辨率比较最高温度、压降和流量；
6. 边界独立性：比较不同入口/出口缓冲长度，确认指标不由开放边界主导。

出口带热代理量不再作为停止判据；能量验证应使用真正的物理能量平衡。

### 4. 物理有效性 Validation 与适用范围

批量扫查计划工况，记录：

- 全局 `Re/Ra/Pr`；
- `tau_u`、流体/固体 `tau_T`；
- 最大与 P99 Mach 数；
- 密度最小值、最大值和相对扰动；
- 最大与 P99 网格 Re；
- 质量与能量残差；
- 收敛步数；
- NaN、Inf、负温度或非物理解；
- 几何最小通道宽度及连通性。

最终形成明确的模拟器适用范围和无效样本过滤规则。

### 5. 求解器与数据格式冻结

进入正式数据生成前应满足：

- 基础解析/标准算例通过；
- 守恒误差可接受且可解释；
- 网格结果收敛；
- 随机复杂结构批量运行稳定；
- 几何与随机种子可复现；
- 失败样本能够自动标记；
- `performance/reliability/regime` 字段及单位固定；
- 模拟器版本或 Git commit 被记录。

冻结后除非发现明确错误，不应在同一数据集中混用不同求解器规则。

### 6. 模型选择与设计阶段

验证完成后进入模型设计。优先明确输入和预测目标：

```text
输入：几何掩码 + 工况参数 + 材料参数
输出候选 A：Tmax、delta_p、Qv 三个标量
输出候选 B：T、ux、uy、rho 完整场，再派生性能指标
```

建议建立两级基线：

1. CNN 编码器 + 多任务回归头，直接预测三个性能指标；
2. U-Net 或 FNO 类模型预测完整物理场，并从场中计算性能指标。

比较完整场预测是否确实改善 OOD 泛化、物理一致性和可微配置优化，而不是预设复杂模型一定更好。

### 7. 后续配置优化方向

模型训练稳定后，将几何参数或连续物态/材料参数作为可微输入，优化：

- 最低最高温度；
- 最低压降或泵功；
- 受约束的体积流量/水力工况；
- 几何可制造性和最小通道宽度。

初期不应把温度和水力代价过早压成一个固定加权分数，建议先观察 `Tmax - pumping cost` 的 Pareto 前沿。
